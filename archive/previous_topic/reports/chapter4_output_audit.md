## A.1 How this audit was produced

1. The final modelling dataset, saved models, hold-out metrics, cross-validation folds, ROC/PR
   curves, confusion matrices, permutation importance and SHAP values were read directly from
   disk.
2. `generate_chapter4_outputs.py` (repository root) was executed end-to-end:
   ```
   python generate_chapter4_outputs.py
   ```
   Result: **42 manifest entries, 0 failures** (`chapter4_outputs/metadata/generation_status.csv`).
3. Raw and processed row/column counts used in the descriptive tables were independently
   re-verified against `data/raw/*.csv`, `data/raw/geo/*.geojson` and `data/processed/*.csv`
   (see §A.4). All matched.
4. Figures were checked programmatically for non-zero size and colour variation so that a plot
   that silently rendered as a single colour would be caught.

These are the points where the original proposal (or the legacy blocks still present in
`config.py`) differ from what was actually implemented. Chapter Four must describe the
**implemented** design and, where useful, note the change.

| # | Proposal / legacy artefact | Implemented reality | Action for Chapter Four |
|---|---|---|---|
| 1 | Unit = **district × month**; target `high_risk` | Unit = **commodity × district × month**; target `price_stress` | State the final unit and target explicitly; cite `commodity_training_table.csv` (10,418 rows). |
| 2 | Rainfall from **WFP FEWS NET province** file | Primary rainfall = **CHIRPS v3 district**; WFP province file retained as legacy EDA only | Present CHIRPS district rainfall as the feature source; province file is contextual. |
| 3 | CV grouped by **province** (as worded in the legacy log) | Primary CV = **GroupKFold by `district_key`** | Report GroupKFold-by-district as primary; StratifiedKFold as reference. |
| 4 | `config.py` `ASSUMPTIONS` **A1–A13** and `high_risk` | Not used by the final pipeline | Label A1–A13 as the **proposal-era assumptions log** and do not present them as results. |
| 5 | Proposal listed six dashboard pages (National Overview, District Risk Map, District Detail, Commodity Detail, Policy Insights, Data Explorer) | Delivered app has **seven** pages; District+Commodity merged; Model Insights + Methodology replace Policy Insights | Include the explicit page-mapping statement (see `whatyouwant.md` §3.13). |
| 6 | Random Forest / Gradient Boosting expected in many proposals | **Blocked** in this environment (Windows Application Control blocked scikit-learn's `_gradient_boosting` DLL); XGBoost used instead | Report the three models actually trained (Dummy, Logistic Regression, XGBoost) and why. |
| 7 | Hyperparameter tuning often assumed | **No tuning performed** — fixed/default parameters | State this plainly (verbatim sentence supplied in `whatyouwant.md` §3.9). |
